# bridge_golden.txt -- what the Android bridge answered for Digi-ID in 4.1.5, frozen (run.sh's GOLDEN leg).
#
# Every line below is the bridge's own answer, read once from the bridge at wallet commit 7210aca86 (4.1.5
# merged into develop; core pin 8014392), before the Coinomi design's step 2 changes how the bridge derives a
# per-site key (docs/superpowers/specs/2026-11-17-coinomi-digiid-design.md). ADDRESS and SIGN lines are
# `digiid_core_bridge print`'s; SWEEP lines are `digiid_core_bridge sweep`'s: the number of answers the bridge
# gave over that part of the fixed stream, refusals included, and the SHA-256 of all of them in order
# (digiid_core_bridge_main.c). The 64-bit and the 32-bit build give the same lines.
#
# run.sh compares these lines with the bridge's on every run, byte for byte and in this order. Lines that
# begin with # are not compared.
#
# DO NOT rewrite a line to make a run pass. A line that differs means an identity moved, or a signature over
# the same bytes with the same key changed: an existing wallet would sign in to a site as another account, or
# be refused by it. Change a line only in the commit that means to move that identity, and say so there.
# A wallet on the upgrade row (per-site root DigiByte, DigiScope identity shared) must keep every line.
#
# THE FIVE SWEEP LINES freeze more than the bridge's answers: each hash also depends on the driver's fixed
# pseudo-random stream (the seed of RNG and the number and order of its draws in digiid_core_bridge_main.c's
# sweep) and on the order in which the three current natives are called (signMessage, signIdentityMessage,
# identityAddress; for the long messages signMessage, signIdentityMessage), so a changed SWEEP hash alone does
# not show that an identity moved. A task that replaces those natives keeps the draws and the call order; if it
# cannot, it re-derives the five lines first, in a commit of its own that changes no production file (bridge,
# core pin): the changed driver still calling the 4.1.5 natives, every ADDRESS and SIGN line above unchanged,
# `digiid_core_bridge sweep`'s new SWEEP lines the same on 64-bit and 32-bit, and the commit saying that the
# stream moved and no identity did. Only then are the natives replaced, against the re-derived lines.
